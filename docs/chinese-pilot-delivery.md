# 中文三界面 Pilot：交付与上线手册

这是一个与原 `/task` 原型分开的 12 题中文试点。三个界面分别是机器型、中性型和高度拟人型；所有组使用完全相同的情境、证据、AI 建议与答案表。组间差异是头像、名称、表达语气及提示的主动性。这里检验的是整套线索包，不能把结果归因于单个线索。

## 立即查看界面

本地启动 `npm run dev -- --hostname 127.0.0.1`，然后打开以下**不保存数据**的预览链接：

- `http://localhost:3000/pilot/1?preview=1`：机器型“决策系统”
- `http://localhost:3000/pilot/2?preview=1`：中性型“智能助手”
- `http://localhost:3000/pilot/3?preview=1`：高度拟人型“小航”

研究者控制台位于 `http://localhost:3000/pilot/admin`。预览链接只用于内部展示，不能作为受试者链接；它们不会记录答案。

已有公开预览域名 `https://humanai-trust-engine.vercel.app`，但它目前是先前部署的版本。只有把当前代码重新部署并复核后，才可将该域名上的三个预览页作为最新 UI 验收。无论部署版本如何，带 `preview=1` 的链接都不保存受试者答案。

## 试点设计与分析约定

这是三组随机分配的**组间**可用性／操纵检验：每人只接触一个界面，不让同一人比较三个角色。建议招募中国大陆、年满 18 岁且能阅读中文的 24–30 人，每组 8–10 人。邀请 CSV 按三组等量生成、打乱分发顺序；各组内 A／B 两种题目顺序尽量均衡。若正式招募页面以外另有资格筛选，应事先固定并对三组相同。每人完成同意、练习、12 道题和 8 项体验评分，预计 15–20 分钟。

| 线索 | 界面 1：机器型 | 界面 2：中性型 | 界面 3：高度拟人型 |
| --- | --- | --- | --- |
| 名称／身份 | 决策系统／自动分析模块 | 智能助手／任务协助界面 | 小航／协作型任务助手 |
| 头像 | 几何机器符号 | 抽象星形符号 | 简化人物头像 |
| 语言 | 无人称、报告式 | 中性协助式 | 第一人称、共同判断式 |
| 主动提示 | 仅提示阶段状态 | 提示浏览证据 | 主动邀请共同查看证据 |
| 灵活度 | 均为同一固定三阶段流程 | 均为同一固定三阶段流程 | 均为同一固定三阶段流程 |

本版不提供自由聊天，也不声称第三组有更强的算法能力。“主动性”是界面线索和措辞；真正的自适应灵活度没有被操纵。三组的题目、证据、推荐方案、解释核心内容、按钮结构和完成路径保持相同。颜色也随线索包变化，因此本轮只能检验**整体拟人化界面包**，不能把效果单独归因于头像、语气、颜色或主动提示。

先看操纵检验：三组在 `humanlike_mean`、`warmth_mean`、`agency_mean` 是否有预期梯度，同时看 `clarity` 是否下降。行为结果重点看 AI 正确时的跟随率、AI 错误时的跟随率（过度信任）、两者之差（校准差）、个人正确率和逐题 `hesitation_time_ms`；`read_time_ms` 用于判断表达长度是否造成阅读负担。报告各组人数、完成率、均值／中位数与个体分布，不将 8–10 人／组的探索性差异解释为确认性因果证据。原始 CSV 支持按任务类别、题目、顺序 A／B、设备和异常时间再审查；本版**没有自动采集设备类型**，需要设备分层时应在招募表另行记录并用匿名参与者 ID 对接。

分析前固定排除规则：撤回记录不分析；主分析只纳入完成 12 题与问卷者，同时报告未完成数；任何题目停留大于 30 分钟或总时长明显异常时，保留原始数据并另做敏感性分析，不静默删除。不要根据参与者是否同意 AI、是否答对或问卷分数事后筛选。正式招募前先用 2–3 名不进入分析的中文测试者走查措辞、移动端与网络恢复，再锁定 `PILOT_VERSION` 和答案表。

## 记录内容与计算口径

这里沿用的 `overtrust`／`undertrust` 字段是错误建议跟随、正确建议拒绝的行为操作化名称。
本流程没有记录每题看 AI 前的独立判断，不能区分原本已持该答案与被 AI 改变的情况，
也不能据一次跟随或拒绝诊断主观信任。请把这些行为比例与信任问卷分开解释；
新版英文两部分实验的前后回答与分析口径见 [两部分实验手册](research-two-part.md)。

每道正式题依次记录情境、证据、AI 建议三个阶段的展示事件和最终决定。`situation_time_ms` 是阅读情境的时间，`evidence_time_ms` 是阅读证据的时间，`read_time_ms` 为两者之和；`hesitation_time_ms` 从 AI 建议显示到点击决定，即本版的**思考时间**；`total_time_ms` 是从情境开始到作答的**总决策时间**。逐题 CSV 另给出易读别名 `thinking_time_ms`、`decision_time_ms` 和兼容旧研究命名的 `latency_ms`。后者与旧 `/task` 的计时起止点接近，但本版扣除了阶段记录的网络等待，跨版本比较时需注明。各阶段计时从界面切换时开始，不包含先前的网络保存等待。刷新页面会恢复已提交的题目，但正在阅读的那一道会重新计时。正式题答复一经保存不可修改；重复网络请求不会生成第二个决定。练习题不计入分析。

服务器按锁定答案表生成 `correct` 和 `ai_correct`，同时把当时的 `ai_reco`、`ground_truth` 与 `stimulus_version` 写入每条决策，防止日后修改题目材料时失去历史判分依据。研究者导出的参与者汇总包含正确率、跟随率、过度信任率（AI 错误时仍跟随）、低度信任率（AI 正确时选择另一方案）、校准差、平均决策／思考／读题时间，以及问卷的拟人感、温暖感、主动性、清晰度和信任评分。逐题 CSV 还包含 `follow_ai` 和 Agent 名称，方便对照原项目的分析字段；阶段事件 CSV 便于审计，完整 JSON 含原始记录。答案表只在服务器模块 `src/lib/pilot-answer-key.ts` 中，不发送给受试者浏览器。

## 本地端到端验证

开发环境没有 Supabase 配置时，pilot 数据写入被忽略的 `data/runs/pilot-local/pilot.json`，仅供本机测试。生产环境**没有数据库配置会拒绝收集**，不会退回到临时文件。

在一个终端运行：

```bash
PILOT_ADMIN_KEY=local-test-key npm run dev -- --hostname 127.0.0.1
```

另一终端运行：

```bash
PILOT_ADMIN_KEY=local-test-key PILOT_BASE_URL=http://localhost:3000 npm run test:pilot:e2e
```

该测试在本机生成 6 条邀请码，用其中 3 条分别完成 12 题，验证 36 条决策、时间字段、6/6 正误平衡、问卷、恢复、重复提交与研究者鉴权。测试产生的是本地 QA 数据，不可混入受试者数据。
本机 QA 服务器应只绑定 `127.0.0.1`，测试后关闭；不要把弱的本地研究者密钥或本地测试链接暴露给局域网用户。

生产构建后可运行 `npm run test:pilot:pagination`。它用本机模拟的 Supabase REST 服务验证新版 secret key 请求头及 1201 条阶段事件的分页导出；这不能替代接入真实 Supabase 项目后的预检。

## Vercel + Supabase 上线配置

1. 在**独立**的 Supabase 项目执行 [`pilot-schema.sql`](../supabase/pilot-schema.sql)。使用由机构批准的数据地区。数据表已启用 RLS，不给浏览器端匿名角色读写策略；数据库密钥只在 Next.js 服务器环境变量中使用。
2. 在 Vercel 项目设置服务器环境变量：`SUPABASE_URL`、`SUPABASE_SECRET_KEY`（或旧式 `SUPABASE_SERVICE_ROLE_KEY`）、一个高强度 `PILOT_ADMIN_KEY`、`PILOT_CONTACT`、`PILOT_DATA_REGION`、`PILOT_RETENTION_DAYS`。不要使用 `NEXT_PUBLIC_` 前缀保存秘密密钥。
3. 先部署并验证 `/pilot/1?preview=1`、`/pilot/2?preview=1`、`/pilot/3?preview=1` 和管理员接口。此时**不要**设置 `PILOT_RECRUITMENT_OPEN=1`；生产环境将拒绝受试者开始，防止未经审核收集数据。
4. 研究负责人批准全部 12 道中文题的正确答案、解释与问卷；机构确认真人参与、知情同意、数据地区和保存期；至少从三种中国大陆设备/网络完成端到端预检。随后才设置 `PILOT_RECRUITMENT_OPEN=1` 并重新部署。
5. 研究者打开 `/pilot/admin`，输入 `PILOT_ADMIN_KEY`，按每组人数生成链接并**立即下载邀请 CSV**。明文邀请码不会保存在数据库中，事后无法重新显示。按 CSV 给每位受试者发一条专属链接；邀请在首次同意后绑定当前浏览器，不能换设备继续。不要把预览链接或同一邀请码群发。
6. 试点期间通过研究者控制台查看每位参与者的完成度、正确率、平均总决策时间与思考时间，并导出参与者、逐题与阶段事件 CSV。导出接口按 500 行分页读取，避免阶段事件超过单次数据库响应上限时截断。招募完成后移除 `PILOT_RECRUITMENT_OPEN`，冻结数据库快照和材料版本，按研究计划分析。

## 招募前必须解决的研究门槛

- `ops_01`–`ops_10` 的中文改写和候选题 `ops_13`、`ops_15` 的正确答案仍是**待研究团队确认的试点材料**，不能把现有程序标签当作经过专业验证的真值。特别核查运营安全与法规歧义，并让不知 AI 建议的人独立审题。
- 知情同意页面必须显示真实联系人、主要数据存放地区与保存期限；研究负责人还要批准完整的招募说明、退出与删除规则。平台日志和数据库备份的保留策略需要与说明一致。
- 中国大陆参与者访问境外服务的可用性，以及个人信息/研究数据跨境处理要求，需由所属机构基于实际部署和数据流确认。未经确认，不要将 Vercel＋Supabase 链接用于外部招募。
- 本轮目标为 24–30 名有效成年参与者，每组至少 8 人；重点是流程、操纵检验和数据完整性，行为差异仅作探索。

## 验收标准

- 三种界面均能从专属链接完成同意、练习、12 题与 8 题问卷，移动端可操作；情境、证据、建议与答案表在三组保持一致。
- 正式数据保存失败时不能无提示进入下一题；刷新后不会重复计入已提交答案。
- 未持有研究者密钥者不能生成链接或导出试点数据；生产环境未配置数据库或未开放招募时拒绝真实收集。
- `npm run lint`、`npx tsc --noEmit`、`npm run build`、`npm run test:pilot:e2e` 通过，并对三种界面各进行一次真人可用性走查。
